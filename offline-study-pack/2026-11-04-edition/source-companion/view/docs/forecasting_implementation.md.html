1# Forecast implementation
2
3The Forecast view (key 5) has the three requested outputs: current on-water race-win probability, pre-race expected position with nonfinish scored N, and the 2027 America's Cup winner. Python produces the probabilities; the browser only selects validated, published artifacts.
4
5## Run locally
6
7Install the locked Python 3.12 environment once. The replay pipeline retains its existing standard-library imports. Core forecasting needs NumPy, SciPy and PyArrow; optional shallow ML packages are locked but not installed by this command. No model weights or external services are needed for verification.
8
9```text
10uv sync --locked --extra forecast-core
11uv run --locked --extra forecast-core python -m pipeline.prediction dataset
12uv run --locked --extra forecast-core python -m pipeline.prediction audit
13uv run --locked --extra forecast-core python -m pipeline.prediction backtest
14uv run --locked --extra forecast-core python -m pipeline.prediction backtest --include-audit
15uv run --locked --extra forecast-core python -m pipeline.prediction build
16uv run --locked --extra forecast-core python -m pipeline.prediction verify
17powershell -ExecutionPolicy Bypass -File run.ps1 verify
18```

28Unsupported scenarios export null values and an explicit reason. Presets select exact values; arbitrary inputs never borrow the nearest forecast. A generated scenario can consequently have the same expectation as the reference; it does not imply a measured weather effect.

30### Generate from the dashboard
31
32With the ordinary local server running (`npm.cmd run dev`), open Forecast, Before the start, select Enter wind conditions, and choose Generate forecast. Existing exact scenarios load immediately. New supported inputs run the existing Python pre-race exporter through `/api/forecast-scenarios`; no source edits or terminal command are required. Progress, retryable errors and exported availability reasons are displayed in the card. Editing inputs cancels that browser's polling and clears the old running state; it does not mislabel an old result as the new conditions.
33
34The service requires the existing local `.forecast/dataset/index.json`, published prediction index, and Python environment. It is installed for Vite development and local preview. A static-only deployment can read existing scenarios but needs the local service to prepare new ones. Forecast JSON and the artifact catalog are read directly from the current public directory in both local modes, so new immutable publications are available without a frontend build.
35
36The current model accepts only a zero direction offset: a course-relative direction response has not passed validation. A request such as 12 knots and 17° is explained before generation and the UI offers an explicit Use 0° offset action. Wind speed support still depends on earlier competitive race coverage. Numeric output remains the conservative zero-effect wind reference where supported; changing wind speed need not change expected positions. Live and Cup forecasts retain their separate targets and evidence gates.
37
38The local endpoint accepts same-origin loopback requests, bounded JSON and catalog race IDs, then launches Python with fixed argument positions and no shell. One workspace lock protects publication across development and preview processes. The child PID is recorded before a startup handshake allows the exporter to run; a live owner or child keeps the lock. An abandoned lock is recovered only after both have exited. The child also owns a ten-minute watchdog. The existing scenario exporter validates and writes immutable objects before replacing the index, preserving all race/live and Cup references. Reports refreshes to include the new scenario and its model/provenance objects.

48A source `started=false`, missing track, reconstructed DNF, OCS or practice stop is not an audited exogenous failure. Official classification and on-water order are distinct targets. Later protest disqualifications do not automatically change the on-water target.
49

Source-confirmed terminal outcomes can be deterministic only when the whole field's valid on-water order/nonfinish states are resolved; the first received finish does not establish that. The UI explains missing evidence instead of displaying a prior as measured reliability. Numeric availability never asserts calibration.
51

Every scheduled asset must appear exactly once with `asset_id`, boolean `started`, boolean `completed`, and `failure_type` (`none`, `exogenous`, or `time_rule`). Unknown causes remain unresolved. Time-rule censoring without an approved exposure treatment prevents the pooled random-failure denominator from being used. Do not fill this file from the dashboard's reconstructed RET/DNF labels. Availability must reflect when the evidence was actually usable.

54## Statistical implementation
55
56`models.py` implements uniform and race-equal empirical references, regularized Plackett–Luce strength, a training-standardized conditional logit comparator, pooled audited Beta-Binomial completion, empirical leg-time regression and a gated positive-delay mixture fitter. Practice fleet sessions under official marks and timing are ingested with a discount weight ($w = 0.5$) for latent ability fitting, preventing 40% sample truncation while keeping competitive regatta titles distinct. Plackett–Luce latent skills use a calibrated empirical-Bayes prior ($\sigma = 1.2$) and discrimination scale ($\kappa = 1.8$) to align simulated order variance with empirical regatta finishing distributions, eliminating artificial rank compression in pre-race expected positions. A completed interval remains a physical observation when its boat later retires. The first interval is gun-to-gate and already includes start loss; no second start delay is added.

58### Ranking Mathematics & Benchmark Invariants
59
601. **Estimand & Winner Assignment Invariant**:
61 The on-water race winner is the fastest boat among valid finishers. If $M < N$ boats finish, the fastest finisher is awarded the win. An internal no-finisher state (`-1`) occurs if and only if **all** boats in the scheduled field fail to finish:
62 $$\text{winners}[(\sim \text{isfinite}(\text{times})).\text{all}(\text{axis}=1)] = -1$$
63 Checking `(~isfinite).any(axis=1)` is strictly prohibited as it erroneously nullifies competitive wins whenever any trailing boat DNFs.
64
652. **Tied-N Rank Sum Identity**:
66 When all $M$ nonfinishers receive tied rank $N$ ($0 \le M \le N$), the realized rank sum of the field satisfies:
67 $$\sum_{i=1}^N R_i = \frac{N(N+1)}{2} + \frac{M(M-1)}{2}$$
68 - When $M = 0$ (all finish) or $M = 1$ (single nonfinisher), the rank sum is identically $\frac{N(N+1)}{2}$.
69 - When $M \ge 2$, the rank sum strictly exceeds the standard permutation sum by exactly $\frac{M(M-1)}{2}$.
70
713. **Analytic Plackett–Luce Expected Rank Benchmark**:
72 Under Plackett–Luce latent skills with weights $w_i = \exp(\theta_i)$ and independent completion probabilities $s_i \in [0, 1]$, the exact analytic expected rank is given by:
73 $$\mathbb{E}[\text{rank}_i] = N(1 - s_i) + s_i \left( 1 + \sum_{j \ne i} s_j \frac{w_j}{w_i + w_j} \right)$$
74 This deterministic formula is implemented in `analytic_plackett_luce_expected_ranks` as a closed-form unit benchmark against Monte Carlo sampling.
75
764. **Contrast Subspace Covariance**:
77 In latent ability sampling (`sample_log_worth`), draws are centered on the zero-sum contrast hyperplane ($\theta \mapsto \theta - \frac{1}{N}\sum_k \theta_k$). This preserves all pairwise contrast variances $\mathrm{Var}(\theta_i - \theta_j) = \Sigma_{ii} + \Sigma_{jj} - 2\Sigma_{ij}$ while anchoring seen entries to zero mean relative to unseen entries.

79### Candidate Ablation & Promotion Evidence
80
81`simulation.py` generates joint complete orders and correlated positive gate times with one persistent crew-form factor, shared race/weather variation at each boat's simulated calendar time and boat innovations. Current remaining and future full legs share their generative prior. Reliability is conditioned on observed survival, DNS is excluded after a known start, and failure exposure uses a normalized constant/transition hazard. Timing limits are separate from exogenous failure. No future XY tracks or opponent arrivals become observed tactical information. Unvalidated tactical coefficients and serial innovation effects remain pooled to zero.

96Both win chances and tied-N expectations come from one joint distribution. An internal no-finisher category preserves total mass. A fixed 0.0001 mixture with a legally valid uniform-order reference regularizes possible tails coherently; terminal impossibilities remain exact. Standard live builds use 20,000 draws and final pre-race scenarios use 100,000. Cup builds explicitly default to 5,000 draws per scenario; their published build budget records the actual draws and seed. The reported 95% Monte Carlo half-width concerns simulation noise only.

98## Causal source contract
99
100Raw ordinal, original timestamp and modeled availability are retained. There is no true receipt clock, so the time basis is explicitly **event-time reconstruction with modeled latency**. The reorder buffer is 6 seconds. A 1 Hz bucket is consumable only once that second has closed; a later sample cannot rewrite a previously published subsecond checkpoint. Live checkpoints are every ten seconds plus source terminal-event checkpoints. Publication is state time plus six seconds. Pre-race observed conditions stop early enough to be available before the gun.
101
102The constant-velocity Kalman filter only moves forward; COG means ground-course direction, not heading. Noise/process settings use earlier observations. Outage masks use earlier-date settings and nonoverlapping truth windows, with separate steady, turning, recovery-proxy and gate strata. Containment/count/date/normalized-error gates certify only a contiguous horizon prefix. No unsupported 60/90-second bridge is assumed. Predicted gate crossings do not confirm phase. Missing opponents stay in the field, and unresolved state suppresses the entire joint forecast.
103
104Mark endpoints use fresh raw fixes with an explicit random-walk variance allowance in crossing uncertainty. Longer mark bridges have not been certified, so the current cap is two seconds, below the planned thirty-second engineering ceiling. Course changes are used only once known. Leg categories are odd/even course segments; the implementation does not assume that the first segment is always upwind. Source coordinate/mark/flag inconsistencies remain quality failures.
105
106`weather.py` separates forecast issue, availability and valid time. Reanalysis is rejected as a historical forecast. No external weather archive has been silently substituted for the observed wind or an explicit scenario.
107
108The dashboard header's sea height and air/water temperatures are separately acquired historical model estimates through `pipeline.environment` ([environment data](environment_data.md)). They provide retrospective replay context and are not inputs to the causal probability model. The Forecast view keeps unavailable-publication diagnostics under “Why this is unavailable”. Available scenario artifacts expose their assumptions, counts and “Unresolved evidence” under “Scenario sensitivity and evidence”.

116### 2027 America's Cup Domain Assumptions & Series Transfer
117
1181. **Class Architecture & Technical Assumptions**:
119 - AC75 hull reuse: Strict one-new-hull rule for the 38th America's Cup (2027); competitors modify existing AC37 generation hulls.
120 - Crew configuration: Reduced from 8 to 5 sailors.
121 - Power generation: Human cyclors removed in favor of stored hydraulic/electrical energy battery systems.
1222. **First-to-7 Match Series Dependence**:
123 Team ability factors are sampled once per tournament trial and held persistent across all match races in a series. Independent per-race ability sampling changes the series win probability by averaging away persistent ability uncertainty (under a 50/50 mix of latent $p \in \{0.5, 0.9\}$, persistent draws yield $\approx 75.00\%$ series win probability, whereas independent draws yield $\approx 93.76\%$).
1243. **Cross-Class Transfer Scaling**:
125 In `cup.py`, `scenario.rho` represents a loading factor onto AC40 ranking effects, yielding realized cross-class correlation:
126 $$\mathrm{Corr}(\theta_{\mathrm{ac40}}, \theta_{\mathrm{ac75}}) = \frac{\rho \cdot \sigma_{\mathrm{ac40}}}{\sqrt{\rho^2 \sigma_{\mathrm{ac40}}^2 + \sigma_{\mathrm{mult}}^2 \cdot \mathrm{scale}^2}}$$
127 Without validated AC40-to-AC75 transfer, reliability, and timing evidence, public Cup probabilities remain unavailable (`null`), with conditional scenario analysis provided in Python.

129## Artifacts and verification
130
131The wire schema is `prediction-1`; Cup is `cup-1`. The index points to immutable content-addressed race, Cup and provenance objects. All objects are written and verified before the index is atomically replaced, preserving the previous publication on failure. Actual source-manifest, model, race and Cup contents are checked against their hashes. The browser checks raw JSON body hashes too, along with complete field/class, status, probability mass, scenario and publication timestamps. Unavailable values are null; missing boats never become zero probability.
132
133Vite excludes the generated forecast directory from file watching to avoid persistent Windows locks during publication. A dedicated development middleware reads forecast JSON directly from the current public directory, including immutable files created after server startup; it does not depend on Vite's watcher-maintained public-file inventory. It preserves exact bytes for hash checks, closes file handles before responding, and returns JSON 404 errors for missing objects instead of the application HTML fallback. Production continues to use exported static JSON. JSON is fetched on view/race selection; refresh an already open Forecast view after rebuilding data. Atomic writes use unique temporary files and bounded retries for transient readers, retaining the previous index on a permanent failure.
134
135Forecast retains all 227 scheduled boat-races, including the three source entries absent from legacy replay telemetry (224 replayed boat-races). The index and each artifact bind the complete scheduled roster and exact replay subset separately. Source-only entrants remain visible in both probability tables and in the rank-N denominator; this does not create synthetic replay telemetry.
136
137Model cards record source/code/lock hashes, training cutoffs, posterior completion, model parameters, outage certification and assumptions. Only active index race/Cup/index payload counts toward the 1.5 MiB target/3 MiB hard browser baseline budget; referenced model/provenance bytes and compressed race bytes are separately reported. Pre-race scenarios have a separate lazy-loaded budget. Builds refresh Reports automatically. Current downloads keep their specific labels, while retained immutable objects are explicitly labeled Forecast archive artifact so every public JSON remains discoverable for readers holding an older index.
138

Foundation models, neural networks and optional shallow ML comparisons remain the research phases defined in [the execution plan](probability_execution_plan.md), not release dependencies.
