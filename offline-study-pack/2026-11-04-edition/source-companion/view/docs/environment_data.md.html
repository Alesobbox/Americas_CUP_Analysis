1# Historical environment data
2
3The replay header combines recorded race wind with separate hourly Open-Meteo
4historical model context: 2 m air temperature, significant wave height and sea
5surface temperature. These fields are model grid estimates, not onboard sensor
6measurements. The requested point is each replay's actual `course.origin`.
7Returned air and marine grid points are retained separately and may differ.
8
9This enrichment is **retrospective replay context only**. It is never imported
10by `pipeline/prediction` or used as weather known before a race. Archived forecast
11runs for causal probability inputs remain a separate task.
12
13## Acquisition
14
15```text
16python -m pipeline.environment
17python -m pipeline.environment --race naples_pr1
18python -m pipeline.environment --race naples_pr1 --force
19python -m pipeline.environment --verify
20npm run environment
21```
22
23The command reads the catalog and a maximum 1 MiB metadata prefix per replay;
24it does not load telemetry arrays or raw source archives. It requests the actual
25UTC replay window's dates, including both dates for a midnight crossing. There
26is no substitution of today's weather or a nearby date.
27
28- Air: [Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api),
29 `https://archive-api.open-meteo.com/v1/archive`, `temperature_2m`.
30- Marine: [Marine Weather API](https://open-meteo.com/en/docs/marine-weather-api),
31 `https://marine-api.open-meteo.com/v1/marine`, `wave_height` and
32 `sea_surface_temperature`, with `cell_selection=sea`.
33
34Requests use UTC Unix timestamps and Celsius. The response must be JSON, at most
352 MiB, and arrive within a 20 second timeout. Units, finite values, nonnegative
36wave heights, sorted unique UTC hours, matching array lengths and requested dates
37are validated. Null provider samples remain null. A failed air request preserves
38valid marine data, and vice versa. Missing dates or hours are not filled by
39borrowing another day's values. A failure is written into the corresponding
40artifact's `errors` object.
41
42## Export and provenance
43
44`public/data/environment/<race_id>.json` uses `environment-1`. Its `hourly`
45object has the sorted union of source `time_ms` values and equally long
46`air_temperature_c`, `wave_height_m`, and `water_temperature_c` arrays. Absent
47samples are null. `units`, `requested_location`, `replay_window`, and
48`context: historical_replay_only` make the interpretation explicit.
49
50Each successful entry under `sources.air` or `sources.marine` records provider,
51`product: historical_model`, exact `request_url`, `retrieved_at` in UTC, returned
52`grid_location`, exact-response `response_sha256`, and a relative `response_file`.
53The raw, unmodified provider bytes are exported at
54`public/data/environment/responses/<sha256>.json` for independent checking.
55
56The request lookup cache is `.forecast/environment/<request_url_sha256>.json`.
57Reuse verifies its URL, timestamp and the raw response's actual SHA-256. A corrupt
58cache fails explicitly; `--force` performs a fresh acquisition. Exported JSON
59uses atomic same-directory replacement. Rebuilding one race preserves the rest.
60The acquisition command also refreshes the Reports download inventory when the
61historical analysis catalog exists, so raw responses remain downloadable.
62
63`--verify` is completely offline. It checks every expected catalog artifact,
64metadata, units, source URLs, grid locations, raw response hashes, and exact hourly
65values/nulls reconstructed from the original responses. A missing artifact or
66tampered response fails verification. Explicit provider failures remain visible
67in its compact coverage summary rather than being converted into fake values.
68
69The free service's [attribution and use conditions](https://open-meteo.com/en/terms)
70apply. The UI attributes Open-Meteo and labels this context as modeled. Ordinary
71unit tests use frozen mock responses and make no live network requests.
